# Регламент аварийного восстановления доступа Создателя (Creator)

Данный документ описывает процедуру гарантированного восстановления управленческого доступа к системе **FunPay Team Dashboard v2.4** в случае потери пароля или непредвиденной блокировки.

---

## 1. Защита Создателя в архитектуре v2.4

Создатель команды (Creator) обладает неизменяемым признаком в базе данных:
- `profiles.is_creator = true` (фиксируется за проверенным `user_id = 34a83ee3-dbc8-49c3-8982-c1ada97f094f`).
- Аппаратный индекс целостности `uq_profiles_single_creator` запрещает существование нескольких Creator.
- Защитный триггер СУБД `trg_fn_protect_profile_fields` блокирует любые клиентские попытки деактивировать Создателя или изменить его роль. Ни второй руководитель, ни сторонний пользователь не могут лишить Создателя прав.

---

## 2. Стандартное восстановление пароля (через Email)

Если Создатель помнит свой email (`kubinovkurtas@...`), восстановление выполняется стандартно:
1. На странице входа нажать «Забыли пароль?».
2. Ввести email и перейти по одноразовой ссылке сброса из входящего письма.
3. Задать новый пароль. Доступ восстанавливается автоматически, все права сохраняются.

---

## 3. Аварийное восстановление через административный скрипт

Если почта недоступна, используется консольный скрипт `scripts/emergency_admin_restore.py`.

### Безопасность:
- Скрипт не содержит захардкоженных токенов и паролей.
- Читает секреты исключительно из защищённых переменных среды текущей терминальной сессии.

### Порядок действий:
1. Откройте защищённый терминал PowerShell или Bash на компьютере администратора.
2. Установите переменные окружения из панели Supabase Dashboard (**Settings → API**):
   ```powershell
   $env:SUPABASE_URL = "https://your-project.supabase.co"
   $env:SUPABASE_SERVICE_ROLE_KEY = "eyJh..."
   ```
3. Запустите скрипт:
   ```bash
   python scripts/emergency_admin_restore.py --new-password "ВашНовыйНадёжныйПароль"
   ```
4. Скрипт атомарно:
   - Проверяет наличие профиля Создателя по неизменяемому UUID;
   - Принудительно выставляет `is_creator = true`, `role = 'owner'`, `is_active = true`;
   - Обновляет пароль в Supabase Auth Admin API;
   - Завершает работу с кодом 0.
5. Войдите в Dashboard с новым паролем.

---

## 4. Восстановление доступа в случае отката миграции 010

Если в базе данных был выполнен откат миграции `010_multi_owner_and_access.sql` (по регламенту [`database/migrations/v2.4/ROLLBACK.md`](../database/migrations/v2.4/ROLLBACK.md)):
- Поле `is_creator` и индекс `uq_profiles_single_creator` в таблице `public.profiles` отсутствуют.
- Система работает в базовой конфигурации single-owner (миграции 001–008), где права определяются наличием `role = 'owner'` и `is_active = true`.

В этом состоянии аварийное восстановление прав руководителя выполняется через прямой SQL-запрос от имени суперпользователя `postgres` / `service_role` в Supabase SQL Editor:
```sql
UPDATE public.profiles
SET role = 'owner', is_active = true, updated_at = NOW()
WHERE user_id = '34a83ee3-dbc8-49c3-8982-c1ada97f094f';
```
Если в системе вообще отсутствовали активные владельцы, также можно использовать функцию bootstrap:
```sql
SELECT public.bootstrap_initial_owner('34a83ee3-dbc8-49c3-8982-c1ada97f094f'::UUID);
```
